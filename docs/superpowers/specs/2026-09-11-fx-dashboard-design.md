# FXトレード・ダッシュボード 設計書

作成日: 2026-09-11

## 1. 目的

Googleフォームで記録している「FXエントリー前記録」と「FX決済後記録」を、
スマホのブラウザで開くだけで成績が一目で分かる画面にする。

メインは**成績のグラフ把握**。その下に全トレードの一覧を置き、
エントリー時の根拠と決済後の振り返りを1トレードとして横並びで確認できるようにする。

## 2. データソース

| シート | ファイルID | 件数(2026-09-09時点) |
|---|---|---|
| FXエントリー前記録（回答） | `16rDRM4K4o4xB3Nz2shItZV0KvYUvC62ObSrUCuf2m1g` | 約118件 |
| FX決済後記録（回答） | `15G63HyUKVho9xBSJ0Ls-CCoXQtLsY7_s6iPBQKYJasE` | 約108件 |

### 列定義

**エントリー前記録**
`タイムスタンプ / 通貨ペア / 方向 / ロット数 / 根拠 / エントリー価格 / 利確価格 / 損切価格 / シナリオが成立しない条件`

**決済後記録**
`タイムスタンプ / 通貨ペア / 方向(エントリー時) / ロット / エントリー日時 / 決済日時 / 結果金額(円) / OCO通り決済か / NOの場合理由 / ①の根拠通りだったか`

### 取得方式

スプレッドシートを「ファイル → 共有 → ウェブに公開 → CSV」で公開し、
発行されたCSV URLをGitHub Pages上のHTMLから`fetch`する。
シートに記録が増えれば、画面を開くだけで反映される。更新作業は不要。

**現状、2つのシートはオーナー限定の非公開。公開設定はユーザーが手動で行う必要がある。**
URLはリポジトリ内の`config.js`に記述する。

### プライバシー上の前提

公開CSVのURLを知る人はデータを読める。GitHub Pagesもpublicリポジトリなら誰でも開ける。
データには損益額と率直な心理メモ（「恐怖決済」「やけくそ」等）が含まれる。
ユーザーはこれを理解した上で公開CSV方式を選択した。URLを他者に共有しない運用とする。

## 3. アーキテクチャ

```
fx-dashboard/
├── index.html              画面構造
├── style.css               スタイル（スマホ縦を基準）
├── config.js               CSV URL 2つ
├── parse.js                CSVパース／金額・日時の正規化（副作用なし）
├── match.js                2シートの突合（副作用なし）
├── aggregate.js            集計（副作用なし）
├── render.js               DOM描画・グラフ描画
├── app.js                  起動・fetch・各モジュールの結線
└── test/
    └── index.html          parse/match/aggregate のテストページ
```

`parse.js` / `match.js` / `aggregate.js` は純粋関数のみ。入力を受けて出力を返し、
DOMにもネットワークにも触らない。これによりテストページから直接検証できる。
`render.js` と `app.js` のみが外部と接する。

データフロー:

```
app.js 起動
  ├→ config.CSV_ENTRY  ┐
  └→ config.CSV_EXIT   ┘ 並列 fetch
        ↓
   parse.parseCsv()        引用符・改行・カンマを含むセルに対応
        ↓
   parse.normalizeEntry() / parse.normalizeExit()
        ↓
   match.linkTrades()      → Trade[] ＋ 未紐付け・要確認のリスト
        ↓
   aggregate.summarize()   期間フィルタを受けて集計
        ↓
   render.draw()
```

## 4. 正規化の仕様（最重要）

実データに表記ゆれがある。推測で埋めず、直せないものは「要確認」として画面に件数を出す。

### 4.1 金額パース `parse.parseAmount(raw)`

実在する全パターン:

| 入力 | 損益 | スワップ |
|---|---|---|
| `1710` | +1710 | 0 |
| `-10000` | -10000 | 0 |
| `-6100(スワップ4940)` | -6100 | +4940 |
| `84000+スワップ17520` | +84000 | +17520 |
| `-9400+2430` | -9400 | +2430 |
| `-200+スワップ3340` | -200 | +3340 |

規則:
1. 先頭の符号付き数値を**トレード損益**とする
2. それ以降に出現する最初の数値を**スワップ**とする（「スワップ」の文字の有無を問わず）
3. 数値が3つ以上ある、または先頭が数値でない場合は `{ ok: false }` を返す

CSV由来のエスケープ（`\-6100` のようなバックスラッシュ）は事前に除去する。
戻り値: `{ ok: true, pnl: number, swap: number }` または `{ ok: false, raw: string }`

### 4.2 日時パース `parse.parseDateTime(raw, fallbackDate)`

実在する揺れ:

| 入力 | 解釈 |
|---|---|
| `2026/09/03 15:47:50` | そのまま |
| `9/3 15:40` | 年が無い → 2026年 |
| `18:02` | 日付が無い → `fallbackDate` を使う |
| `9/9 8/58` | `:` が `/` のtypo → `9/9 8:58` として解釈 |
| `9/9 9:5` | 分が1桁 → `9:05` として解釈 |

年は全レコード2026年。

`fallbackDate` の与え方:

- **エントリー日時**に日付が無い場合 → そのレコードのフォーム送信タイムスタンプの日付
- **決済日時**に日付が無い場合 → 同レコードの**エントリー日時**の日付
  （実データの `9/3 17:52 → 18:02` のようなケース。決済がエントリーより前の時刻になる場合は翌日とみなす）

日付も `fallbackDate` も得られない場合は `{ ok: false }`。

### 4.3 突合 `match.linkTrades(entries, exits)`

決済後記録の各行に対し、エントリー前記録から次の条件で候補を絞る:

1. 通貨ペアが一致
2. 方向が一致
3. ロットが一致

候補のうち、決済記録の`エントリー日時`とエントリー記録の`タイムスタンプ`の差が最小のものを採用する。
差の上限は **7日**（IFO待機で8/18記録→8/19発動のようなケースを拾うため）。

1件のエントリー記録が複数の決済記録の候補になりうるため、**全組み合わせを時間差の昇順に並べ、
差が小さいペアから順に確定させる**（確定済みの決済記録・エントリー記録は以降の候補から外す）。
決済記録の並び順に依存しない、決定的な結果になる。

候補が無い場合は `entry: null` とし、画面には「エントリー記録なし」と表示する。
推測で別のレコードを当てはめることはしない。

決済記録に紐付かなかったエントリー記録は**保有中ポジション候補**として別に保持する（将来利用）。

## 5. 集計仕様

期間フィルタ（全期間／今月／今週／直近7日）を適用した上で算出する。
期間の判定には**決済日時**を使う。

| 指標 | 定義 |
|---|---|
| トレード損益合計 | `pnl` の総和 |
| スワップ合計 | `swap` の総和 |
| 合計 | 上記2つの和 |
| トレード数 | 対象レコード数 |
| 勝率 | `pnl > 0` の件数 ÷ トレード数（`pnl == 0` は勝ちに数えないが分母には含む） |
| 平均利益 | `pnl > 0` の平均 |
| 平均損失 | `pnl < 0` の平均（絶対値） |
| リスクリワード比 | 平均利益 ÷ 平均損失。負けトレードが0件の場合は `-` と表示（0除算を避ける） |
| 最大勝ち / 最大負け | `pnl` の最大 / 最小 |

**勝率とリスクリワード比はトレード損益(`pnl`)のみで計算する。**
スワップを混ぜると判断の良し悪しが見えなくなるため。スワップは別枠で総額を表示する。

金額パースに失敗したレコードは全集計から除外し、「要確認 N件」として画面に出す。
0円として扱うことはしない。

### グラフ

1. **日別損益 棒グラフ** — 決済日ごとの `pnl` 合計。プラスとマイナスで色を分ける。
2. **通貨ペア × 方向 の比較** — データに実在する組み合わせを動的に抽出して表示する
   （現状はドル円買い・ドル円売り・メキシコペソ円買いの3区分だが、新しい通貨ペアが増えても自動で増える）。
   組み合わせごとに損益合計・トレード数・勝率を横棒＋数値で表示。

ライブラリは Chart.js をCDNから読み込む（バージョン固定）。

## 6. 画面構成（スマホ縦を基準）

上から順に1カラムで積む。

1. **期間フィルタ** — `全期間 / 今月 / 今週 / 直近7日` のトグル
2. **サマリータイル** — トレード損益・スワップ・合計の3数値を大きく。
   その下に 勝率／トレード数／平均利益／平均損失／RR比／最大勝ち／最大負け
3. **日別損益 棒グラフ**
4. **通貨ペア × 方向**
5. **全トレード一覧** — 決済日時の新しい順。1件1カード。
   - 折りたたみ時: 日時（エントリー→決済）／通貨ペア・方向・ロット／損益額／根拠の冒頭1行
   - タップで展開: エントリー前記録の全項目（根拠・エントリー価格・利確価格・損切価格・シナリオが成立しない条件）と、
     決済後記録の全項目（OCO通り決済か・NOの場合理由・①の根拠通りだったか）
   - エントリー記録が紐付かない場合は「エントリー記録なし」と明示

PCで開いた場合はコンテンツ幅を広げ、グラフを横に並べる（レスポンシブ）。

## 7. エラー処理

| 事象 | 挙動 |
|---|---|
| CSV取得失敗（ネットワーク／未公開） | 画面に原因と対処（公開手順）を表示。白画面にしない |
| 金額パース失敗 | 集計から除外し「要確認 N件」を表示。一覧では該当カードに「要確認」バッジ |
| 日時パース失敗 | 同上。日別グラフからは除外 |
| 突合できない決済記録 | 集計には含める（損益は確定しているため）。一覧で「エントリー記録なし」 |
| データ0件 | 「記録がありません」を表示 |

## 8. テスト

`test/index.html` をブラウザで開くとアサーションが走り、結果が一覧表示される。
外部フレームワークは使わず、小さなアサーション関数を自前で持つ。

- `parse.parseAmount` — 上記6パターン＋失敗ケース2つ
- `parse.parseDateTime` — 上記4パターン＋失敗ケース1つ
- `parse.parseCsv` — 引用符内のカンマ・改行・エスケープされた引用符
- `match.linkTrades` — 完全一致／数分ズレ／7日ズレ／候補なし／同条件が複数ある場合の取り合い
- `aggregate.summarize` — 手計算できる5件程度のデータで全指標を検証。
  パース失敗レコードが除外されることも確認する

## 10. セットアップ手順（実装後にユーザーが行う）

1. 各スプレッドシートで `ファイル → 共有 → ウェブに公開` を開く
2. 公開対象を該当シート、形式を `カンマ区切り形式 (.csv)` にして公開
3. 発行されたURL 2つを `config.js` に貼る
4. GitHubにリポジトリを作成しpush、Settings → Pages を有効化
5. 発行されたPages URLをスマホのホーム画面に追加
