# 記録フォーム改造 設計書

作成日: 2026-11-05

## 目的

エントリー前と決済後の記入の手間と迷いを減らし、集計しやすい形で記録する。過去の記録はそのまま読み取れる状態を保つ。

## エントリー前フォーム

| 質問 | 変更 | 形式 |
|---|---|---|
| 通貨ペア、方向、ロット数、根拠 | 変更なし | 現状のまま |
| エントリー価格 | 数字のみにする | 短文、数値チェック |
| 注文方法 | 新設 | 選択: 成行 / IFO |
| 利確pips | 利確価格から置き換え | 選択: 30 / 40 / 50 / その他 |
| 損切pips | 損切価格から置き換え | 選択: 20 / 30 / 35 / 50 / その他 |
| いつまで持つ？ | 「シナリオが成立しない条件」から分離 | 選択: 当日中 / 今週中 / OCO到達まで / その他 |
| OCO以外で動くならどんなとき？ | 同上 | 短文、任意 |

## 決済後フォーム

| 質問 | 変更 | 形式 |
|---|---|---|
| 通貨ペア、方向、ロット、OCO通り決済か、根拠通りだったか | 変更なし | 現状のまま |
| エントリー日時 | 形式チェックを追加 | 短文、`M/D H:MM` または `H:MM` |
| 決済日時 | 任意にし、形式チェックを追加 | 同上。空欄なら送信時刻を使う |
| 結果金額(円) | 数字のみにする | 短文、整数チェック |
| スワップ(円) | 新設 | 短文、任意、整数チェック。空欄は0円 |
| NOの場合理由 | 選択式にする | 任意。恐怖決済 / 損切り切り上げ / 期限 / その他 |

## ダッシュボード

- 新しい列は列の位置ではなく見出し名で読み取る。既存の列は従来どおり位置で読み取る。
- 過去の記録は、利確価格、損切価格、成立しない条件、金額欄のスワップ表記をそのまま読み取る。
- 利確と損切は、新しい記録ではpipsで表示する。エントリー価格を読み取れれば、方向とpipsから計算した価格も併記する。1pipsは0.01円とする。
- スワップ欄と金額欄の両方にスワップが書かれた記録は、二重計上を避けて要確認にする。
- 決済日時が空欄なら送信時刻を決済日時とする。
- 時刻だけの決済日時は送信日の日付を使い、送信時刻より後になる場合は前日とする。

## 年の扱いの修正

年なしの日付は2026年に固定せず、送信タイムスタンプの年を使う。その結果が送信時刻より半年を超えて未来になる場合は前年とする（例: 2027/1/2に記録した `12/31 23:00` は2026年）。数日先の打ち間違いまで前年扱いにしないよう、幅を半年にする。

## 進める順番

1. ダッシュボードを新旧どちらの形式でも読めるように更新し、公開する。
2. フォームを変更する。
3. 公開CSVの見出しに新しい列が出ることを確認する。実データを汚さないよう、テスト記録は送らない。新形式の読み取りはテストと再現データで確認し、最初の実記録でも確認する。

## テスト

`test/parse.test.js` で新旧の列、空欄、二重計上、年またぎを検証する。公開シートの実データで既存の238件の集計が変わらないことを確認する。
